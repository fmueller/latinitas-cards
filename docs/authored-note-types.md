# Authored note types and safe import

This is a manual reference setup for `specs/v0.1.1.md#authored-note-kinds`,
not a new CLI command or an automatic Anki note-type installer. Create a new,
dedicated note type for each kind; never reuse a legacy or principal-parts type.
One authored item yields one note and one `Recognition` card, with no reverse card.

`LatinitasID` is always the first matching field. Managed fields contain content,
opaque provenance, language, and generation metadata. `Source Key` is the normalized
explicit key; `Source Kind` is `vocab`, `form`, or `qa`. `Document`, `Section`, and
optional `Reference` preserve the input's labels rather than looking up a corpus.
`Note Schema` is `authored-1`, independent of the principal-parts schema;
`Generator` and `Profile` record the supplied generator version and effective
profile digest. Metadata does not affect identity.

`Personal Notes` is the final, user-owned field: **never map it during import**.
It is omitted entirely from `RenderedAuthoredNote.to_export_fields()`, not emitted
as an empty value. Tags travel separately as Anki tags metadata and are not a regular
field. Repeat imports must match the same dedicated type on the first field and
update managed fields only. Back up the collection first. This contract does not
implement CSV writing or Anki import; those pipeline stages must preserve this split.

Managed values are HTML-escaped plain text, with newlines converted to `<br>`.
Enable HTML when importing those values; do not escape them a second time or treat
authored text as executable HTML. Personal Notes remain user-managed Anki content.
Use your preferred Anki styling: the templates need no special CSS to work.

For a form occurring in different contexts, assign distinct keys (for example
`lesson:3:sentence:1:form:amat` and `lesson:3:sentence:2:form:amat`) even if text forms
match. Citation corrections with the same key, namespace, and kind preserve identity.
An optional dictionary form appears on the vocab front; optional form context appears
on the form front. The back adds the answer, optional citation, and Personal Notes.
Empty optional fields produce no empty labeled blocks.

The reference below is generated by `reference_authored_note_types()` from the
authoritative module and tested against it. Create exactly the listed fields and
one template per type; do not add reverse templates if you want the default one-card
contract.

## `vocab` — Latinitas Authored Vocabulary

Create these regular fields in this exact order:

```text
LatinitasID
Lemma
Dictionary Form
Meaning
Document
Section
Reference
Source Key
Source Kind
Language
Note Schema
Generator
Profile
Personal Notes
```

Create exactly one card template, named `Recognition`.

Front:

```html
<div class="lemma">{{Lemma}}</div>
{{#Dictionary Form}}<div class="dictionary-form">{{Dictionary Form}}</div>{{/Dictionary Form}}
```

Back:

```html
{{FrontSide}}
<hr id="answer">
<div class="meaning">{{Meaning}}</div>
{{#Reference}}<div class="reference">{{Reference}}</div>{{/Reference}}
{{#Personal Notes}}<div class="personal-notes">{{Personal Notes}}</div>{{/Personal Notes}}
```
