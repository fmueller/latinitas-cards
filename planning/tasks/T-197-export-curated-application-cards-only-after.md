# T-197-export-curated-application-cards-only-after Export curated application cards only after rendered approval

## Description

P50-6 curated preview/recipe/export. Own deterministic application and mnemonic-recall
recipes, approval bindings and withdrawal integration. Share provenance/export safety,
not automatic policy. Follow approved contracts and spec execution/validation requirements.

## Acceptance

- Default emphasizes rule application to Latin/context; mnemonic recall is opt-in.
  Each recipe has one objective. Preview prompt, answer, mnemonic, explanation,
  caveats and provenance; save effective recipes/selection for reruns.
- Export requires explicit pair AND actual rendered-card approval. Unchanged approvals
  persist; wording/caveat/rendered-content changes require renewal, including theme/
  presentation changes under the approved policy.
- Preserve item identity across corrections and distinct recipe/semantic exercise
  keys, CSV ownership and personal notes. Do not duplicate free-form qa intake.
- Withdrawal/invalidation uses receipts and supported managed/manual handoffs.
  Automatic linguistic success cannot bypass either human gate.

## Verification Notes

Exercise neither/pair-only/rendered-only/both approval cases, unchanged rerun, content/
theme edits, recall opt-in, withdrawal and personal-field preservation through public
preview/export. Run the mandatory validation chain.
