# T-230-verify-complete-request-accounting-with-offline Verify complete-request accounting with offline provider fakes

## Description

Extend T189's offline integration coverage for complete serialized provider-request
accounting under specs/v0.5.0.md#cli-orchestration-and-provider-boundaries.
Use fixture-only service accounting, not real provider token qualification.

## Acceptance

- Strict offline fakes compare bound input with dispatched bytes for all three
  supported protocols, including non-ASCII task data and chat/schema framing.
- Independently derived input plus reserved output costs distinguish exact and
  one-less ceilings, asymmetric roles, cumulative retries and unknown calls.
- Durable reservations survive reopen and fake usage/output cannot refund them;
  completed calls replay without dispatch or renewed reservation.
- Production missing-token-bound behavior remains unchanged. No real inference,
  model/tokenizer download, qualification, judge, policy or publication work.

- Run final ruff, mypy and pytest gate before supported verify/complete; record
