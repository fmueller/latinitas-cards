# LatinitasCards v0.9.0

## Summary

Planned release candidate. Freezes the intended v1 contracts, validates them against varied
decks and Latin domains, completes migration and operational documentation, and focuses on
correctness and reproducibility rather than new feature breadth.

## Goals

- Prove the deck-first and corpus-first workflows on realistic data.
- Finalize schemas and compatibility boundaries intended for v1.0.
- Verify Anki update safety and reproducible corpus/card generation.
- Produce complete user, agent, and maintainer documentation.

## Potential Features

### Real-World Compatibility Matrix

Test multiple CSV/APKG/COLPKG layouts and biblical, classical, late-antique, and medieval
corpora. Cover German and English generated content, USFX and the supported TEI subset,
file-based Anki imports, and optional direct integration. Record known unsupported layouts
and format constructs explicitly.

### Identity And Update Safety Audit

Verify deterministic IDs, no-duplicate regeneration, managed/user field separation,
conflict detection, retirement tag/suspend behavior, note-type/template stability, and
scheduling preservation. Include interrupted/retried apply and upgrade scenarios.

### Schema And Migration Freeze

Freeze candidate v1 schemas for profiles, recipes, manifests, normalized corpora, sidecar
annotations, plans, generated notes, and machine-readable CLI output. Provide migrations
from the final supported pre-1.0 schemas and clear errors for unsupported older files.

### Reproducibility And Performance

Test deterministic outputs, corpus indexing and ranking performance, large-deck memory use,
offline behavior, optional network boundaries, and resumable agent workflows. Every
non-deterministic field is documented and excluded from semantic comparisons.

### Documentation And Release Operations

Complete tutorials for deck-first and corpus-first projects, updates and conflicts, recipes,
themes, confidence/review, agent automation, file and direct Anki workflows, backups, and
recovery. Refresh licensing/provenance documentation and define the v1 release checklist.

## Caution

- Late schema changes may be justified by correctness, but require explicit migration and
  another release-candidate cycle.
- Sample decks and corpora must be sanitized and redistributable.
- Passing unit tests is not a substitute for importing and updating in supported Anki.

## Recommendation About LLM Support

Validate LLM-off operation as the baseline. Test optional LLM paths for provenance,
redaction boundaries, failure fallback, and policy enforcement without making model output
part of the stable correctness oracle.

## Explicitly Excluded

- Broad new recipe families or corpus adapters.
- New required hosted services.
- GUI or Anki add-on work unrelated to v1 contract validation.
- Compatibility promises before the v1 schemas are formally released.
