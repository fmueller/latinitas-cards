# LatinitasCards v0.3.0

## Summary

Planned release. Establishes a source-independent Latin corpus model and an agent-ready CLI
contract. USFX/Vulgate becomes the first adapter to that model rather than a special-purpose
generation path.

## Goals

- Preserve arbitrary biblical, classical, late-antique, and medieval Latin sources with
  complete provenance.
- Keep source files immutable while humans and agents iterate on annotations.
- Give agents deterministic, non-interactive, policy-controlled CLI workflows.
- Separate corpus identity from mutable text and formatting.

## Potential Features

### Normalized JSONL Corpus Model

Define a versioned JSONL interchange model for corpus, work, passage, sentence, token,
citation, period/register, source language, and optional target-language content. Passage
identity uses corpus namespace plus source-native passage ID. Sources without stable IDs
receive persistent manifest-assigned IDs. Content hashes detect corrections without
changing passage identity.

Source-native segments remain available even when generation defaults to one sentence.
Citation must represent verse, section, line, or other work-specific schemes without
forcing every corpus into a biblical book/chapter/verse model.

### USFX Normalization

Normalize the bundled Clementine Vulgate and other USFX inputs into the shared model. The
adapter preserves source identifiers and citations and produces the same normalized schema
that later TEI, CSV, plain-text, or download adapters use. Existing Vulgate workflows remain
available during migration but are no longer the architectural center.

### Sidecar Annotation Model

Store segmentation, morphology, syntax, translations, corrections, confidence, and review
state in versioned sidecars linked by stable passage/token identity. Source corpora remain
unchanged. Sidecars retain analyzer/agent provenance, model or rule version, timestamp,
input hash, confidence state, and human approval where applicable. A derived enriched
corpus can be exported for interoperability, but it is not canonical.

### Agent-Ready CLI Contract

Provide non-interactive commands with versioned JSON/JSONL inputs and outputs, stable exit
and error codes, deterministic plan/apply behavior, idempotent reruns, and no hidden prompts.
Agents propose annotation patches or plans against immutable inputs. Human-readable output
remains available separately, and effective project configuration is always reportable.

### Policy-Gated Agent Automation

Agents may apply only operations allowed by the project profile and confidence policy.
High-confidence, non-destructive changes can flow automatically; conflicting, destructive,
or insufficiently calibrated changes enter review. Every applied result remains traceable
to its source and producer.

## Caution

- Token and sentence boundaries can change after corrections; sidecar references need
  explicit invalidation/reconciliation behavior.
- Source-native IDs may collide across editions unless namespaced.
- Agent throughput must not bypass the same validation and ownership rules used by humans.
- JSONL is the interchange contract, not an excuse to discard source XML metadata.

## Recommendation About LLM Support

Treat LLMs as optional annotation producers behind the same sidecar and provenance
contract as deterministic analyzers. Core normalization, validation, identity, and
plan/apply remain offline and provider-independent.

## Explicitly Excluded

- TEI XML ingestion.
- Corpus-first Anki card generation.
- Automatic acceptance of all agent or LLM output.
- Required hosted services.
- Direct Anki integration.
