# LatinitasCards v0.1.0

## Summary

Active spec. Covers the first release of the CLI: an end-to-end pipeline that turns an
existing Anki deck or CSV export into corpus-based cloze cards — `inspect`, `split`,
`annotate`, `cloze`, `preview`, `generate`, `validate`. The pipeline, the Anki package
readers (including `anki21b`/zstd), the CLTK annotation path with optional Ollama
disambiguation, and the ruff/mypy-strict/pytest gates are all in place and green.
`pyproject.toml` already reads `0.1.0`, but no tag, release, or changelog exists, and two
option paths that ship in the CLI have no regression coverage. What remains is closing
those coverage gaps and release hygiene.

## Goals

- Ship the split -> annotate -> cloze pipeline as an installable CLI that a learner can run
  against their own deck without manual spreadsheet work.
- Cover every shipped option path with regression tests, not just the defaults.
- Keep the checks green under the pinned toolchain (ruff, mypy strict, pytest on 3.10–3.12).

## Potential Features

### Deck Inspection And Splitting

`inspect` reports note types, fields, and a head-like sample from `.apkg`, `.colpkg`, or
CSV input. `split` turns multi-form notes into one-note-per-form records, writing CSV or
rewriting an APKG in place while preserving the original notes, and overwrites the source
and front fields with the split form.

### Grammar Annotation

`annotate` adds CLTK lemma, POS, and morphology columns. LLM disambiguation against a local
Ollama endpoint is opt-in (`--use-llm`) and falls back to the CLTK candidate when the
endpoint fails. CLTK/Stanza resources are a runtime prerequisite, not a package dependency.

### Corpus Cloze Generation

`cloze` generates cloze examples per form from USFX XML, plain text, or parallel CSV
corpora; `preview` samples without writing output; `generate` writes Vulgate clozes back to
CSV or APKG-compatible output. Multi-cloze per verse, word-form expansion, lemma-form files,
and ignore patterns are covered by tests.

### Difficulty And Translation Options

`--difficulty easy|medium|hard` filters cloze complexity and `--latin-column` /
`--translation-lang` / `--parallel-mode` bring translations in from a parallel corpus. Both
ship in the CLI and neither has direct regression coverage: only the non-interactive
ignore-with-warning path for parallel columns is tested today.

### Module Extraction

`commands/` holds one module per command, but each is a shim re-exporting `<name>_impl`
from `cli.py`, which is still ~2200 lines — well past the 800-line ceiling in AGENTS.md.
The implementations and the domain helpers around them still need to move out.

### Release Hygiene

There is no `CHANGELOG.md`, no `v0.1.0` tag, and no GitHub release, while
`pyproject.toml` already declares `0.1.0`. Cutting the release means reconciling changelog,
tag, and docs against the shipped command set.

### Commit Policy Hooks

Local git hooks are managed by lefthook, pinned in `mise.toml`, replacing the `pre-commit`
framework. `pre-commit` runs ruff, ruff format, mypy, and `taskrail validate`, and refuses
agent author identities and staged merge markers. `commit-msg` enforces Conventional Commit
subjects, a body wrapped at 72 characters, `(T-NNN)` task suffixes, and no attribution
trailers. `pre-push` rescans outgoing commits for attribution and agent authorship, then runs
pytest. Each guard script under `scripts/` carries a test suite that CI runs.

### uv Toolchain

The project environment is managed by uv, pinned in `mise.toml`, replacing Poetry.
`pyproject.toml` uses standard `[project]` metadata, a `dev` dependency group, and the
setuptools build backend; `uv.lock` is the dependency source of truth. CI installs with
`uv sync --locked --dev`, and the migration keeps every locked package version unchanged.

## Caution

- `annotate` depends on CLTK/Stanza resources and the optional LLM path on a running Ollama
  endpoint; a failure there is an environment issue first, not necessarily a regression.
- Difficulty filtering and parallel-column handling touch the same cloze selection path — a
  fix on one side can silently re-break the other, which is exactly why both need coverage.
- APKG rewriting mutates user decks; the preserve-originals behavior is load-bearing.
- `cli.py` is shared by every command, so extraction work is broad-blast-radius and needs
  the full ruff/mypy/pytest chain per step.

## Recommendation About LLM Support

Keep the LLM seam optional and single: one OpenAI-compatible/Ollama endpoint configured by
flags, never required for a successful run, always falling back to the deterministic CLTK
candidate. No provider-specific SDKs.

## Explicitly Excluded

- Publishing to PyPI or shipping prebuilt binaries.
- A GUI or an Anki add-on.
- Languages other than Latin, or flashcard formats other than Anki.
- Bundling corpora beyond the Clementine Vulgate sample.
- Persisted state or a database; every command stays file-in/file-out.
