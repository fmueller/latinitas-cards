# LatinitasCards v1.0.0

## Summary

Planned stable release. Establishes compatibility promises for deck-first and corpus-first
Latin study-card generation, safe managed updates, recipes and themes, normalized corpora,
provenance, agent automation, and supported Anki file/direct workflows. v1.0 signifies a
stable core contract, not completion of every possible feature.

## Goals

- Make generated identities, updates, and user-data ownership trustworthy over upgrades.
- Support repeatable study projects built from existing decks, Latin corpora, or both.
- Keep automation auditable, policy-controlled, and usable without network services.
- Publish versioned schemas with documented migration and deprecation rules.

## Potential Features

### Stable Project And Generation Contracts

Profiles, recipes, manifests, themes, plans, generated-note schemas, and effective
configuration output are versioned compatibility contracts. Supported v1 files migrate
forward across compatible releases. Breaking changes require an explicit major-version or
documented migration path; files are never silently interpreted under the wrong schema.

### Stable Identity And Ownership

Source entries, corpus passages, annotations, and generated exercises retain stable logical
identity independently of mutable text and local Anki IDs. Regeneration does not create
duplicates. Managed fields update through plans; personal fields are preserved. Conflicts
require resolution, and retired notes are explicitly tagged and suspended rather than
deleted.

### Supported Deck-First Workflow

Inspect and profile existing CSV/APKG/COLPKG layouts, generate principal-part and supported
grammar/form exercises, preview deterministic plans, and deliver them through supported
Anki file workflows or optional direct integration. Stable note-type/template contracts
preserve scheduling and exercise meaning.

### Supported Corpus-First Workflow

Normalize supported structured corpora, preserve source-native citations, maintain immutable
sources plus sidecar annotations, and generate ranked context/analysis/translation cards
without requiring an existing deck. Deck and corpus identities can be linked without being
conflated.

### Auditable Human And Agent Automation

Human-readable and versioned JSON/JSONL CLI contracts expose the same deterministic
plan/apply operations. Agents operate under project permissions and calibrated confidence
policies. Every generated or applied claim retains source and producer provenance. Core
workflows remain offline; downloads and LLM interactions are explicit opt-ins.

### Stable Language And Presentation Model

CLI controls remain English. Generated content supports German and English with explicit
language tags. Themes map separate morphology and syntax semantics to accessible visual
styles without embedding presentation in linguistic identity. The model remains extensible
to other output languages without promising them in v1.

### Migration And Operational Guarantees

Document supported versions, backup/recovery, deterministic regeneration, conflict handling,
retirement, schema migration, deprecation windows, and rollback limits. Release validation
covers supported Python and Anki versions plus representative deck and corpus fixtures.

## Caution

- Stable contracts constrain future design; only behavior proven in the v0.9 compatibility
  matrix should enter the v1 promise.
- Linguistic annotations remain evidence-based and may require review; v1 stability is not
  a claim of perfect automatic Latin analysis.
- Optional provider and corpus integrations have external availability and licensing risks.

## Recommendation About LLM Support

Keep LLM support optional, provider-independent, provenance-rich, confidence-gated, and
unable to bypass plan/apply or ownership rules. The complete stable workflow must remain
usable with LLM features disabled.

## Explicitly Excluded

- Perfect or exhaustive automatic analysis of all historical Latin.
- Every corpus format, TEI customization, dictionary, or target language.
- Automatic grading of free translations as uniquely correct.
- Silent deletion, synchronization, or destructive updates.
- A GUI or Anki add-on as a prerequisite for the supported CLI workflow.
- Network services as a requirement for core operation.
