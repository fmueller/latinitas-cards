# LatinitasCards v0.7.0

## Summary

Planned release. Turns profiles, corpora, recipes, themes, and manifests into portable,
reproducible study projects that humans and agents can resume across machines and software
runs without losing provenance or silently changing generated selections.

## Goals

- Reproduce a generation plan from declared inputs and configuration.
- Make project state portable without bundling private decks or restricted corpora by
  default.
- Resume long-running corpus and agent workflows safely.
- Explain how every generated note relates to source entries, passages, recipes, and runs.

## Potential Features

### Portable Project Bundles

Define a project layout for versioned profiles, recipe selections, themes, corpus manifests,
sidecar references, ranking policies, and generation metadata. Exportable project bundles
contain configuration and checksums by default; private or licensed source content is
included only through an explicit option and policy check.

### Reproducible Generation Locks

Record effective configuration, source checksums, adapter/analyzer versions, recipe versions,
language settings, ranking policy, optional model identifiers, and semantic output hashes.
A lock explains drift between runs without making timestamps or machine-local paths part of
generated-note identity.

### Resumable Batch Workflows

Support checkpointed corpus normalization, annotation, ranking, card planning, and export.
Retries are idempotent and resume from validated artifacts. Agents and humans use the same
run manifest, and partial output cannot be mistaken for an applied complete plan.

### Relationship And Provenance Reports

Report relationships among source lexical entries, corpus passages, annotations, generated
exercises, Anki notes, recipes, and generation runs using stable logical IDs. Reports are
available as readable summaries and versioned JSON without depending on local Anki card IDs.

### Project Validation And Portability Checks

Validate missing sources, checksum drift, unsupported schemas, unavailable optional models,
language mismatches, unresolved conflicts, stale sidecars, and non-portable paths before a
run. Provide actionable remediation instead of silently regenerating different material.

## Caution

- Reproducibility metadata can expose private paths or source names unless redacted.
- A lock file records inputs and decisions; it must not become a credential store.
- Exact byte reproducibility may differ from semantic reproducibility and must be labeled.
- Bundling source material has copyright and privacy implications.

## Recommendation About LLM Support

Record provider/model/configuration and input/output hashes when optional LLM processing is
used, while keeping credentials out of projects. Reproducibility means traceability of an
LLM-assisted run, not a promise that a hosted model will return identical text forever.

## Explicitly Excluded

- Embedding credentials in project files or bundles.
- Implicit redistribution of source decks, corpora, or translations.
- Cloud-hosted project storage as a core requirement.
- Treating machine-local Anki IDs or paths as portable identity.
