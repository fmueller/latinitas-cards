# LatinitasCards v0.1.1

## Summary

Planned release. Adds import of authored study notes: vocabulary, form-identification, and
free question/answer items that a learner or an agent has already written, for example in
Markdown lecture preparation. Authored notes reuse v0.1.0's stable identity, note-field
ownership, preview, and deterministic CSV export contracts instead of introducing a
parallel output path. The import is corpus-agnostic: source references are opaque
citations, and no bundled corpus is required or assumed.

## Goals

- Turn authored vocabulary, form, and question/answer material into Anki notes that can be
  re-imported repeatedly without duplicates.
- Let a human decide, before the first import, which and how many items become cards.
- Keep extraction from loosely structured notes outside the binary: an agent skill produces
  a strict, versioned import file, and the CLI only validates, previews, and exports it.
- Remember selection decisions so repeated extraction does not reintroduce skipped items.

## Potential Features

### Authored Note Import Format

LatinitasCards accepts a human-readable, versioned JSONL import file with one authored item
per line and a `schema_version`. Every item carries:

- a `kind` of `vocab`, `form`, or `qa`;
- an explicit, stable `key` chosen by the author or agent;
- the kind-specific content fields;
- provenance: source document label, source section label, and an optional source
  reference;
- a selection `status` of `include` or `skip`;
- optional tags; and
- an explicit language tag for learner-facing content.

The source reference is an opaque citation string such as `Lk 1,28`, `Cic. Cat. 1,1`, or
`Lektion 3`. LatinitasCards stores, displays, and filters on it verbatim but never parses,
validates, or resolves it against a corpus. Section labels are likewise free text taken
from the source document. Incompatible schema versions and malformed items fail clearly
with the line number and failed assumption.

### Authored Note Identity

Each authored item's `LatinitasID` is derived from a configured collection namespace, the
item kind, and the item key. Content fields, wording, tags, status, provenance text, and
file position do not participate in identity, so corrected answers or glosses update the
same logical note on re-import.

Keys are normalized deterministically before identity is derived. Two items with the same
namespace, kind, and normalized key are one logical item: identical or compatible content
is merged and reported, while conflicting content is an error that names both lines. An
identity is never reassigned to a different key.

Compatible duplicates have equal required content, language, document label, and section
label. An absent optional content field or source reference may be filled from another
item; different nonempty values conflict. Tags are combined, deduplicated, and sorted;
`skip` takes precedence over `include`. Merging is independent of input order, and filters
operate on the merged item. Conflicts identify the differing fields and both lines.

### Authored Note Kinds

The initial kinds and their default card directions are:

1. `vocab`: lemma, optional dictionary form (for example genitive and gender or principal
   parts), and meaning; the card goes from Latin to meaning.
2. `form`: text form, base form, grammatical analysis, translation, and optional context;
   the card goes from the form, shown with its context when present, to base form,
   analysis, and translation. Contextually distinct occurrences of the same text form
   require distinct explicit keys, including when source references differ. Changing a
   source reference alone does not change an established item's identity.
3. `qa`: question, answer, and optional source reference; the card goes from question to
   answer.

Each kind has its own dedicated, stable note type. All of them share the v0.1.0 note
contract: `LatinitasID` in the first field, managed content fields, source provenance,
generation metadata, and a user-owned personal-notes field that later imports never
overwrite. Personal Notes is omitted from generated CSV columns, not exported as an
empty value, and remains unmapped during import. Reference field definitions and
front/back templates document how to create each note type with one card per item.

### Authored Note Selection And Preview

Before writing output, LatinitasCards validates the import file and previews it without
side effects. The preview reports counts by kind, source section, source reference, and
status; merged duplicates; invalid or conflicting items with reasons; and representative
rendered cards.

Validation and duplicate reconciliation cover the whole file before selection, including
skipped and filtered-out items. Preview reports recoverable line-level errors together
and exits nonzero if any validation or conflict error remains; any cards shown in that
case are diagnostic, not an exportable selection. Export also exits nonzero on such
errors and creates or modifies no output files.

Selection filters by kind, source section, source reference, and tag narrow what is
exported without editing the file. Items marked `skip` remain in the import file and are
never exported, so a later extraction that preserves keys does not reintroduce them.
Export writes deterministic, UTF-8 Anki-import CSV through the v0.1.0 export boundary and
reports the effective selection. An empty selection is reported without writing output.
CLI documentation shows validation, preview, and export with an explicitly configured
collection namespace; no corpus resources or principal-part field mappings are required.

### Authored Note Extraction Skill

A repository agent skill turns loosely structured Markdown study notes into the import
format. It handles varying heading names, table column names, bullet-list vocabulary, and
question/answer material whose answers appear inline or in a separate solutions section.
It proposes keys by documented conventions, preserves existing keys and `skip` decisions
when re-extracting into an existing import file, and runs validation and preview before
reporting back. The skill makes no corpus-specific assumptions and never writes to Anki
directly. Synthetic first-extraction and re-extraction fixtures demonstrate a corrected
answer, an existing skipped item, a new item, and a missing item, with preserved keys and
statuses and an accurate new/changed/missing report.

## Caution

- Keys are the identity contract; an agent that silently renames keys creates duplicates.
  Free question/answer items have no natural key and need explicit, reviewed keys.
- Loosely structured notes vary between documents; deterministic Markdown parsing in the
  binary would be brittle, so extraction stays in the agent layer.
- Once notes are imported into Anki, removing them requires v0.2 managed updates;
  selection must happen before the first import.
- Authored content is trusted as written. LatinitasCards does not verify grammatical
  analyses or translations.
- One authored item remains one note/card by default.

## Recommendation About LLM Support

The binary stays LLM-free. Extraction and key proposal happen in the agent skill; the CLI
validates, previews, and exports deterministically. Human review of the preview decides
what is exported.

## Explicitly Excluded

- Markdown parsing inside the CLI.
- Interpreting, normalizing, or resolving source references against a corpus.
- Retiring or deleting previously imported notes.
- Direct updates to a live Anki collection.
- A stable JSON preview contract for agents; that remains v0.3 work.
- Automatic verification of authored grammatical content.
